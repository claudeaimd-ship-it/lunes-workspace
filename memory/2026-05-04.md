## Dashboard de Trazabilidad (Machine_db)

### Contexto
- Polo pidió crear dashboard web de trazabilidad desde Machine_db (SQL Server 2022 en 172.24.217.240)
- Stack: FastAPI backend + HTML/CSS/JS vanilla frontend
- Datos fuente: tablas BigDataBalancer11-18, G3Datas_v2, G4Datas, MachinePartDetails

### Problemas resueltos
1. **Nombres de columnas con espacios** → aliases en SQL (`[MOTOR CODE] AS MotorCode`)
2. **Palabras reservadas SQL Server** (`USER`, `CURRENT`) → alias `BalUser`, `BalCurrent`
3. **Se consultaba como lectura** (solo SELECT, política de solo lectura respetada)
4. **Timeout de conexión** → login_timeout=5, timeout=10 en pymssql
5. **SIGKILL en execs largos** → los comandos que duran >30s mueren. Subí a ~4s usando exec con yieldMs

### Archivos creados
- `~/dashboard/server.py` — Backend FastAPI en puerto 8000, endpoints:
  - `GET /api/trazabilidad` — datos paginados con filtros
  - `GET /api/trazabilidad/search` — búsqueda por código
  - `GET /api/trazabilidad/detail` — detalle de motor con balanceos + pruebas eléctricas
- `~/dashboard/trazabilidad.html` — Frontend con navbar, filtros, column toggle, tabla paginada, modal de detalle

### Túnel público
- Polo no podía acceder desde su red → túnel con **localhost.run** (serveo.net falló, cloudflared requiere login por navegador)
- URL pública generada: **https://2f7dac61ff7ad8.lhr.life** (temporal, cambia al reiniciar túnel)
- Comando: `ssh -R 80:localhost:8000 nokey@localhost.run`
- HTTPS automático, sin abrir puertos en firewall

### Pendientes
- Polo dijo que le gustaría Cloudflare Tunnel con autenticación para URL fija y más seguridad
- Considerar systemd service para el dashboard
- Considerar persistencia del túnel público

### Lecciones aprendidas
- **pymssql con as_dict=True** devuelve dicts con keys = los alias del SELECT (no los nombres originales)
- **Palabras reservadas SQL Server** hay que escaparlas con brackets Y usar aliases que no choquen
- **localhost.run** es la opción más rápida para túneles públicos sin auth
- Para túneles persistentes usar cloudflared (requiere login browser en setup)
- Los execs de OpenClaw matan con SIGKILL por timeout (30s) — usar process(action=poll) o yieldMs para largas duraciones

## Túnel público (localhost.run) — auto-recuperación

### Problema
- El dashboard se cae → `BindsTo` mata el túnel → systemd no lo reinicia por exit code 0
- Cada reconexión a localhost.run genera **URL nueva** (no fija)

### Soluciones implementadas
1. **tunnel-wrapper.sh**: Script bash con loop infinito que reconecta siempre tras 10s de espera
2. **Eliminación de `BindsTo`** en el unit de systemd: el túnel ahora es independiente del dashboard
3. **trap en wrapper**: Siempre sale con exit code 1 para que systemd reinicie (nunca code 0)

### Problemas restantes
- localhost.run tiene rate limit: reconexiones rápidas repentinas causan "already in use" y bloqueo temporal (~30s)
- URL cambia cada reconexión: https://80fcee47cbf7d5.lhr.life → https://bc2e34c948bcc6.lhr.life → https://55228aa8845a4a.lhr.life
- Polo reportó "no tunnel here" dos veces (frustrante para él)
- Pendiente intentar Cloudflare Tunnel (URL fija) cuando Polo lo autorice
